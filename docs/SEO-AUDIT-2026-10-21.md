# Auditoría SEO técnico y on-page — 21/10/2026

## Cambios por tarea

1. El loading global se limita al panel. Las consultas de páginas públicas son Server Components; el título, descripción, contenido y proyectos no requieren hidratación. El contador de visitas es accesorio.
2. Sitemap con rutas canónicas, áreas activas y proyectos publicados; robots conserva el acceso a medios públicos y excluye rutas privadas. Plantillas duplicadas antiguas se sustituyen por redirecciones permanentes.
3. ProfessionalService (subtipo de LocalBusiness) con Cusco, teléfono, correo y redes existentes. Dirección limitada a ciudad, región y país; sin calle, coordenadas, reseñas o precios inventados. BreadcrumbList y Service en servicios; proyectos conservan su grafo y migas.
4. Intención distinta por servicio, marca y Cusco en páginas generales; un H1 visible por vista. Se conservan overrides SEO deliberados del panel.
5. Cuatro páginas con alcance, proceso, preguntas visibles y CTA; FAQPage se genera de los mismos datos. Google limita los resultados enriquecidos de FAQ a ciertos sitios gubernamentales/sanitarios: el schema no garantiza FAQ en resultados.
6. Se prioriza la primera imagen hero y se evita su aparición inicial desde opacity:0; las demás mantienen carga diferida. Se conservan dimensiones/aspect-ratio y protección de /api/media. Alternativas descriptivas sustituyen nombres de archivos; imágenes decorativas mantienen alt vacío. Las métricas de campo se comprueban en Search Console, no se inventan mejoras numéricas.
7. Correcciones conservadoras de errores conocidos en texto público y contenido enriquecido. No se sobrescribe la base de datos ni se modifica texto de credenciales o URLs.
8. Una cifra SSR por contador, derivada del catálogo real. Se eliminan las copias de números para lectores de pantalla que se concatenaban al extraer texto.
9. Fichas internas enlazadas incluso cuando el proyecto apunta a una web externa; servicios relacionados y contacto.
10. Canonical absoluto en el dominio público, OG/Twitter consistentes y sin duplicar la marca. Búsqueda interna con noindex y enlaces rastreables.

## Despliegue y operación

Se conserva el postbuild de Hostinger que prueba los alias de dependencias y carga hbuilds/config/.env. No se versionan secretos. La suite completa pasó (71 pruebas) usando la instancia MySQL local dedicada; las pruebas no se ejecutaron contra producción. Se corrigió el Origin ausente en una petición de prueba para respetar la protección CSRF existente. No ejecutar seeds ni migraciones de contenido sobre producción.

Tras desplegar, comprobar HTML sin JavaScript en /, /servicios y los cuatro servicios: un H1, texto de alcance/FAQ, canonical, schemas y enlaces; robots, sitemap, favicon y salud. En Search Console, inspeccionar las cuatro URLs, revisar canonical elegido y enviar sitemap. Consultar consultas, impresiones y posición por URL. No se garantiza puesto, indexación o plazo.

Fuentes: https://developers.google.com/search/docs/essentials/technical ; https://developers.google.com/search/blog/2023/08/howto-faq-changes ; https://web.dev/articles/optimize-lcp ; https://web.dev/articles/optimize-cls

## Verificación

- Lint y TypeScript: correctos.
- Suite completa: 17 archivos y 71 pruebas correctas sobre MySQL local dedicado.
- Auditoría HTTP sin JavaScript: 12 rutas con HTTP 200, un H1, canonical correcto y OG/Twitter completos. Los cuatro servicios incluyen texto de alcance y FAQ visible en HTML que coincide con FAQPage. Se verificaron dos proyectos locales.
- La primera medición de laboratorio encontró CLS 0, SEO 100 y LCP móvil simulado 5,4 s, con aviso de CPU lenta y pruebas concurrentes. No representa una mejora medida en usuarios reales. Se eliminó el runtime de animación público usado solo por la barra de lectura; ahora usa CSS scroll-driven y respeta movimiento reducido.
- Prueba reproducible de HTML: python3 scripts/check-public-seo.py http://127.0.0.1:3140. Se puede indicar https://codexcusco.com después del despliegue.
